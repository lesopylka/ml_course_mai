## Защита работы

На защите необходимо **понимать собственное решение**.

Преподаватель может попросить:

- объяснить любой фрагмент Notebook;
- объяснить принцип работы использованной модели;
- объяснить выбранную метрику, её отличие;
- объяснить назначение train/test split;
- объяснить, что такое переобучение;
- объяснить смысл feature importance;
- интерпретировать конкретный результат или график;
- изменить небольшую часть эксперимента и предположить, как это повлияет на результат.

> Использование LLM и других вспомогательных инструментов само по себе не освобождает от необходимости понимать решение.
>
> Работающий код, происхождение и смысл которого студент не может объяснить, **не является достаточным основанием для высокой оценки**.

 

## 11. Что считается некорректным решением

Особое внимание будет уделяться **корректности эксперимента**.

### К критическим ошибкам относятся, например:

- использование целевой переменной среди входных признаков;
- использование информации из тестовой выборки при обучении;
- подбор решения непосредственно по результатам на скрытом тесте;
- вычисление преобразований на всём датасете, если таким образом информация из тестовой части попадает в обучение;
- сравнение моделей на разных разбиениях без обоснования;
- некорректный расчёт метрики;
- отсутствие baseline;
- невозможность объяснить происхождение полученного результата.

> ⚠️ Если вы получили необычно высокое качество, это **не обязательно** означает, что вы нашли отличную модель.
